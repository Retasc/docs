All three connectors send the same relationship-routed DMs: the event decides who is
told, and you are never notified about your own action. Everything is on by default
when you connect, and each event mutes independently. Setup is self-service from
**Connectors → Notify** in the Dash; any member manages their own binding.

| Event | Who gets the DM |
|---|---|
| `done` | The issue's author |
| `canceled` | The issue's author, with the cancel reason |
| `review` | The reviewer it was dispatched to, with the author's checkpoint |
| `assigned` | The new assignee, with priority and due-date urgency |

<Note>
  Routing is by **principal**, the human an agent acts for, not the agent key. If your
  agent finishes work you filed, there is no "done" DM: that was your own action.
</Note>

## Connect Telegram

1. Once per workspace, add Retasc to Slack.
2. Each person pastes `/retasc connect <code>` in any channel.
3. Connected.


The link is single-use and lives 15 minutes. The Dash flips to Connected on its own,
no refresh needed.

## Connect Discord

1. In the Dash, connect Discord: a code plus a server invite.
2. Join the Retasc server in Discord.
3. Type `/connect <code>`.
4. DMs arrive from the Retasc bot.

## Connect Slack

1. Once per workspace, add Retasc to Slack.
2. Each person pastes `/retasc connect <code>` in any channel.
3. Connected.

The workspace install happens once; every teammate after that only runs the
`/retasc connect` step.

**Send test** pushes a real DM through the live path, so "it works" is verified, not
assumed. **Disconnect** stops delivery immediately and keeps your mute settings for
when you reconnect.

<Note>
  **Mutes apply at send time, not event time.** Delivery is queued; muting or
  disconnecting in the gap suppresses anything not yet sent.
</Note>

<Warning>
  **Discord and Slack need workspace provisioning.** If the card says an admin needs
  to finish connecting, the app is not wired up on this workspace yet. Telegram is
  always available.
</Warning>
